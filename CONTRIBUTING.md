# Contributing

## Principles
1. Prefer Microsoft Learn, Microsoft Security, service descriptions and official announcements.
2. Record the verification date when behavior, licensing or preview status can change.
3. Separate GA capability, Preview capability, architectural recommendation and lab assumption.
4. Practical examples must state prerequisites and expected outputs.
5. Never commit tenant secrets, IDs, production tokens or customer data.

## Pull requests
A technical guidance PR should state which official sources were checked, what changed, and whether labs/templates are affected.
