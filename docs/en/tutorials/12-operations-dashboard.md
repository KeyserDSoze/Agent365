# Tutorial 12 — Operations Dashboard

## Goal

Use the golden-agent evidence export to build an operational view without adding a backend to the static site. The dashboard runs entirely in the browser.

## Evidence export

```http
GET /api/evidence/export?limit=200
```

The bundle contains schema version, generated timestamp, `capturesContent=false`, summary, runs, tool audit and tool registry.

Current schema:

```text
agent365-golden-agent-evidence/v1
```

## Bundled sample

The repository includes `examples/evidence/operations-sample.json`, copied automatically into the Pages artifact.

## Load a real export

In the **Operations** section, choose **Load JSON export** and select a file generated by the golden agent. Parsing happens locally in the browser and no static-site backend receives the data.

## KPIs and drill-down

The view shows run count, success rate, average latency, failures and tool invocation/allow/deny counts. Run detail shows conversation ID, trace ID, provider/model, duration, input/output sizes and tool decisions correlated by run ID.

## Privacy

The export contract declares `capturesContent=false`. The dashboard is designed for metadata-only evidence and does not require prompts, responses or complete tool arguments.

## PowerShell example

```powershell
$evidence = Invoke-RestMethod -Uri "http://localhost:5080/api/evidence/export?limit=200" -Method Get
$evidence | ConvertTo-Json -Depth 20 | Set-Content ".\lab-output\operations-export.json"
```

When API-key protection is enabled, include the `X-Api-Key` header.

## What it is not

The dashboard does not replace Agent 365 observability, Defender, Purview Audit, SIEM/SOC tooling or production retention. It is intended for training, demos, POCs and local troubleshooting.

## Definition of Done

- v1 evidence export generated;
- `capturesContent=false`;
- bundled sample loads;
- real export can be imported;
- KPI values match evidence;
- status/provider filters work;
- run drill-down works;
- tool decisions correlate by run ID.
